## The consensus problem: small-M verification is not free on Metal

| finding | source | status |
|---|---|---|
| MLX `qmv_wide` (0.32.0) reuses dequantized groups for M=2..limit; 1.1–1.6× over per-row qmv at M=2 | [mlx #3764](https://github.com/ml-explore/mlx/pull/3764) | merged |
| Still 1.03× / 1.47× / 2.69× of M=1 cost at M=2/4/8 (M4 Pro, 4096×24576) | [mlx #3839](https://github.com/ml-explore/mlx/issues/3839) | 3P |
| Marginal row is FMA/issue-bound (~40% fp32 peak); a custom `metal_kernel` couldn't beat `qmv_wide`; closed as not a "real case" | [mlx #3852](https://github.com/ml-explore/mlx/issues/3852) | 3P |
| BM=16 qmm tile: 1.65× at M=10–16 (M3 Max) — closed unmerged | [mlx #3863](https://github.com/ml-explore/mlx/pull/3863) | C |
| llama.cpp MTP on Metal is a net loss (−11…−28%, Qwen3.5-9B) | [llama.cpp #23752](https://github.com/ggml-org/llama.cpp/issues/23752) | 3P |
| mlx-lm native-MTP PR: depth 2 loses to depth 1 because verify slope grows faster than acceptance | [mlx-lm #990](https://github.com/ml-explore/mlx-lm/pull/990) | C |
| EAGLE-3 in MLX: 1.05×, 34% acceptance | [mlx-lm #890](https://github.com/ml-explore/mlx-lm/discussions/890) | 3P |

**Our measurement agrees** (M4 Max, Qwen3.5-4B): stock MLX step cost at M=8 is 2.45× M=1, and
draft-model speculation in mlx_lm nets 1.0× (K=2,4) and 0.71× (K=6).

## Gaps nobody has shipped on MLX (what this repo targets)

1. An MMA-based verify kernel with ~flat cost up to M=8 → **built here** (`skinny_mlx/qmm.py`).
2. Native MTP depth ≥ 2 — only profitable once verify is flat (#990's failure mode).
3. Hybrid rollback without per-token state snapshots or full replay.
4. Pruned-vocabulary draft head so K draft tokens don't pay K full 248k-row LM heads.
